# Conservative document extraction CLI

Решение задания A — LLM Engineer из тестового задания WhiteList. CLI получает текст документа и возвращает JSON по фиксированной схеме. В текущей версии не используется внешний API или платный ключ: конвейер локальный и детерминированный, а все результаты проходят Pydantic-валидацию. Это сделано сознательно, чтобы поведение было воспроизводимым и чтобы отсутствие модели не превращалось в выдумывание данных.

## Запуск с чистой папки

Требуется Python 3.11+.

```powershell
python -m pip install -r requirements.txt
python -m pip install -e . --no-deps
```

Извлечь один текстовый файл:

```powershell
extract-document --input data\01_invoice.txt
```

Или без установки entry point:

```powershell
python -m llm_engineer.cli --input data\01_invoice.txt
```

При наличии локально запущенного Ollama можно явно выбрать его, например:

```powershell
extract-document --ollama-model llama3.2:3b --input data\01_invoice.txt
```

Этот режим обращается только к `127.0.0.1:11434`; ответ модели не принимается без проверки `DocumentResult`. Внешние API и ключи не нужны.

Проверить весь набор:

```powershell
python -m llm_engineer.cli --eval data
```

Команда печатает точность по каждому полю, число галлюцинаций и число пропусков.

## Схема результата

Результат содержит `doc_type`, `supplier_name`, `supplier_bin`, `doc_number`, `doc_date`, `currency`, `total_amount`, `vat_amount`, `line_items`, `field_confidence` и `warnings`. Все неизвестные скалярные значения — `null`; `line_items` — пустой массив, если позиции отсутствуют. `supplier_bin` принимается только как ровно 12 цифр. Значения, для которых обнаружено противоречие или OCR-ошибка, не исправляются догадкой: поле остаётся `null`, а причина записывается в `warnings`.

Правило для нескольких итогов: если есть «Всего к оплате», используется он; иначе берётся первый явно обозначенный итог, а различие фиксируется в `warnings`. НДС не вычисляется самостоятельно.

## Тестовый набор

В `data/` находятся 10 пар `*.txt` и `*.json`: три документа из задания и семь дополнительных. Дополнительные кейсы покрывают отсутствующие поля, сумму прописью, смешанный казахско-русский текст, OCR-ошибку в БИН, валюты USD/EUR, конфликтующие итоги и неизвестный документ.

Тесты:

```powershell
pytest
```

## Что сделано и что не сделано

Сделано: фиксированная схема, программная валидация, консервативный локальный extractor, warnings/confidence, 10 эталонных документов, eval, unit-тесты и CLI. Также добавлен необязательный адаптер локального Ollama; OCR изображений и production-grade мониторинг не входят в реализацию. Для тестового задания внешний API необязателен; default-путь остаётся локальным и воспроизводимым.

Ограничение времени — 4 часа чистой работы. Поэтому решение не добавляет авторизацию, БД, веб-интерфейс или необязательные интеграции.
